## Contained `start.ps1` runtime acceptance

The project launcher was exercised against the accepted rebuild installation with `Qwen/Qwen3.5-0.8B`. `-ValidateOnly` passed under Windows PowerShell 5.1 and PowerShell 7, and inherited runtime/cache overrides were replaced by contained process-local values.

A first laboratory run used the long repository checkout as the containment root and exposed a Windows legacy-path constraint: with `LongPathsEnabled=0`, PyTorch AOT atomic rename failed at a 261-character destination. An isolated probe reproduced the exact boundary with the same Python and parent directory: 258/259-character paths succeeded, while 260/261/262 failed with `FileNotFoundError` / `WinError 3`. No global setting was changed.

Acceptance was repeated with short root `C:\AI\v5`, representative of the canonical install layout, using an independent copy of the model cache. Results:

- server reached `127.0.0.1:8131` through `start.ps1`
- `GET /v1/models`: HTTP 200 in 142 ms
- first `POST /v1/completions`: HTTP 200, 16 tokens, output begins with `Dublin`; cold lazy JIT cost about 54.1 s
- second warm completion: HTTP 200 in 278 ms, output begins with `Dublin`
- contained caches were actively populated (`cache\vllm`: 122 files / 73,255,911 bytes; `cache\triton`: 1,543 files / 68,124,584 bytes at capture time)
- full before/after metadata snapshots of `%USERPROFILE%\.cache\vllm`, `%USERPROFILE%\.cache\huggingface`, `%USERPROFILE%\.cache\torch`, `%USERPROFILE%\.triton` and `%USERPROFILE%\.deep_gemm` reported **zero changes** both during live inference and after shutdown
- scoped laboratory process-tree cleanup removed launcher, vLLM, API server and EngineCore processes and closed the test port

This validates real OpenAI-compatible serving through the contained launcher without writing runtime cache state back into the user's profile.
Reviewer regression coverage additionally verified under both Windows PowerShell 5.1 and PowerShell 7 that:

- the exact caller process environment is restored after `-ValidateOnly`, a successful child exit, and a failing child exit
- the child process still receives contained cache/temp variables while it is running, with inherited `PYTHONPATH` and `PYTHONHOME` cleared

## Important limitations

- FA3 is intentionally absent because the upstream FA3 path does not support Blackwell SM120.
- DeepGEMM 2.6.1 Windows binary/JIT plumbing is built and importable, but upstream DeepGEMM has no SM120 runtime dispatch. Real `bf16_gemm_nt(...)` therefore reports `Unsupported architecture`; SM120 must not be routed into the SM100 backend blindly.
- This milestone accepts only one GPU. Windows NCCL, Tensor Parallel and Pipeline Parallel remain future work.
- A non-fatal PyTorch/c10d hostname connection warning (`WinError 10049`) remains visible during world-size-1 initialization and should be investigated before release polish.
