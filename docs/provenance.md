# Provenance

Every tested runtime bundle must record, at minimum:

- official vLLM upstream repository and exact tag/commit;
- project Windows patchset revision;
- Python ABI/version;
- PyTorch version and CUDA runtime variant;
- Triton Windows version;
- all downloaded artifact URLs, effective URLs, sizes, and SHA-256 digests;
- build environment and build inputs for project-built artifacts;
- validation hardware and test results.

Community Windows ports may be used as research/reference sources. Any copied code or patch material must retain applicable license/copyright notices and be documented explicitly.

## Runtime dependency materialization acceptance

`bootstrap-dependencies.ps1` materializes the committed lock only from a receipt-backed exact unseeded `runtime/venv`. It validates the exact lock size/SHA, pinned managed CPython and uv identities, physical managed paths, and the complete deterministic base-venv receipt contract before mutation. The live venv is never synchronized or removed in place while the replacement is being built: pinned uv creates a relocatable replacement under managed staging and performs `pip sync` with required hashes, wheels only, `link-mode=copy`, strict validation, contained cache/config state, and Python downloads disabled. Only after exact distribution validation and `uv pip check` succeed does activation briefly move the live venv to a deterministic managed backup and promote staging. Dependency receipt schema v2 records every deterministic identity/policy field, is cryptographically bound to the exact historical base-venv receipt bytes, and carries the same transaction generation ID as the durable transaction receipt.

The 2026-09-14 acceptance campaign exercised the transaction in both PowerShell 7 and Windows PowerShell 5.1 with a hashed `colorama==0.4.6` fixture. Coverage included exact unseeded-base rejection for extra files, happy-path materialization, exact caller-environment restoration, idempotence, deterministic dependency-receipt field tamper rejection, base-receipt byte-drift rejection, unexpected-distribution rejection, lifecycle-lock contention, package-hash failure rollback, receipt-commit failure rollback, forced replacement, and forced offline replacement from the contained cache. Four explicit interrupted-process disk states were also reconstructed: mid-materialization, after backup but before activation, after activation but before dependency-receipt commit, and after dependency-receipt commit but before cleanup. Uncommitted generations rolled back to the prior runtime; a committed generation cleaned stale staging/backup state without rolling back the active environment.

A separate fresh-root acceptance then materialized the real 28-package canonical lock from an empty venv/cache. uv resolved and installed exactly 28 packages, verified every required hash, and `uv pip check` reported all installed packages compatible. Independent metadata inspection returned exactly 28 distributions. The environment reported PyTorch `2.13.0+cu130`, CUDA `13.0`, RTX 5090 compute capability `12.0`, successful CUDA arithmetic, and Triton `3.7.1`. After the crash-recovery hardening, the previously accepted schema-v1/non-relocatable 28-package root was upgraded with `-Force -Offline` to the relocatable schema-v2 transaction model. The v2 environment again reported exactly 28 distributions, RTX 5090 CC `12.0`, Torch `2.13.0+cu130`, CUDA `13.0`, and Triton `3.7.1`; staging, backup and transaction receipts were absent after commit. A subsequent offline rerun was idempotent and left the schema-v2 dependency receipt byte-identical.
